## What this is

Phone-first migraine tracker. Wins by collecting less: one-tap start/stop capture, auto-enriched context (time, weather, barometric pressure), optional voice note. Analysis (trigger engine, trends, doctor export) is deterministic and exposed to Claude through an MCP server.

## Stack

- **Language:** TypeScript
- **Front end:** Vite + React 19, Tailwind v4, `vite-plugin-pwa` (installable, offline outbox)
- **Backend:** Hono on a Cloudflare Worker, nightly cron for the weather backfill
- **Database:** Cloudflare D1 (SQLite), migrations in `migrations/`
- **Services:** Open-Meteo (weather + barometric pressure, no API key), Web Speech API

## Layout

```
src/shared/   <- types and pure logic shared by client + worker (ICHD-3, meds, cycle, stats, health, format)
src/worker/   <- Hono app (index.ts), MCP server (mcp.ts), trigger engine, insights, export, days backfill
src/client/   <- Today (App.tsx), AttackSheet, History, Insights, HeadMap, outbox, voice, time module
migrations/   <- D1 schema, 0001..0008 (additive only)
scripts/      <- Obsidian import/export, health CSV import, icon generation
test/         <- Vitest (d1-adapter runs migrations on node:sqlite)
.dev.vars     <- local-only ACCESS_PIN (gitignored; copy from .dev.vars.example)
```

## How to run

```bash
npm install
cp .dev.vars.example .dev.vars
npm run migrate:local           # apply D1 migrations to the local database
npm run dev:worker              # wrangler dev on :8787 (serves API + built client)
npm run dev                     # vite on :5173, proxying /api to :8787
npm test                        # unit + integration suite
npm run build                   # tsc + vite build (dist/client) + PWA service worker
```

Redeploy: `npm run deploy`. Remote schema changes: add a migration, then `npm run migrate:remote`. Rotate the PIN: `wrangler secret put ACCESS_PIN`. The Worker refuses every API request when `ACCESS_PIN` is unset.

Scripts that talk to a deployed instance read `AURA_URL` and `AURA_PIN` from the environment and default to local dev.

## Location timeline

`scripts/lib/timeline.mjs` and the seed in `migrations/0004` hold an EXAMPLE timeline, and a test keeps them in sync. Production keeps its real rows in the `locations` table. A real timeline for the importer lives in a gitignored `*.local.mjs` file and is never committed.

## MCP server

`/mcp` (JSON-RPC 2.0, streamable-HTTP). Auth: `Authorization: Bearer <ACCESS_PIN>`, or `?token=<ACCESS_PIN>` for connectors that cannot set headers. **The MCP server is the insights engine:** Aura computes deterministic statistics and Claude narrates them, so no health number is generated by a model.

Tools: `get_overview`, `summary`, `monthly_headache_days`, `headache_days_trend`, `list_episodes`, `search_notes`, `self_reported_triggers`, `premonition_stats`, `premonition_conversion`, `trigger_analysis`, `belief_vs_data`, `day_of_week`, `time_of_day`, `medication_response`, `menstrual_analysis`, and the two writes `log_premonition` and `log_period_start`.

**The tool descriptions carry the epistemic guardrails**, because Claude narrates from them. If what the data means changes, change the description. In particular: these are headache days, not migraine days; self-reported triggers are beliefs, not evidence; partial months are excluded from trends; stats report `enough_data: false` rather than concluding from thin data.

## Public repo rules

- No personal data in code, tests, fixtures, docs or commit messages: no real places, dates of moves, episode counts, diary text or names. Fixtures use invented data.
- Never commit `.dev.vars`, exported episode data, import SQL or `*.local.mjs`.

## Gotchas

- Do not add comprehensive logging fields. The app is designed to ask for as little as possible.
- Migrations are additive. Editing an applied migration does not re-run it in production.
